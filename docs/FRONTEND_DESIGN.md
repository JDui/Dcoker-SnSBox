# 前端设计说明

状态：2026-11-15 按用户指定 RC UI Style 2.0 更新；Sol Max 线程实施，主线程独立检查。实际实现与验证见 FRONTEND_IMPLEMENTATION.md。

## 用户指定规范

前端遵循 [RC UI Style Skill 2.0](https://github.com/JDui/RC-UI-Style-Skill/blob/aa8ed8e052c7d105ff531ab968e248ec4b7f286d/skills/rc-ui-style/SKILL.md)。本轮读取该固定版本的视觉系统、组件、文案、动效连续性与验收规范；参考图仅用于布局与材质，不复制其文案或演示数据。

- 高频聊天工具采用 `restrained`；正文和会话使用稳定实色或 flat，导航和弹层可使用少量轻玻璃。保留现有品牌强调色与浅深主题。
- 圆角分为控件、卡片、面板三级，使用细描边与轻阴影；状态与筛选可使用胶囊，不扩散到所有按钮。
- 标题写模块名，按钮写动作，状态写真实结果；删除宣传口号、拟人化与无信息修饰，保留登录、只读资料与不确定结果的必要说明。
- 动效只用于反馈和局部过渡；快速切换以最终输入为准。减少动效时直接呈现终态；不支持模糊时使用可读的实色回退，媒体本体不加滤色。
- 验收以桌面、390px 触屏、浅深主题、键盘与减少动效的实际证据为准；未测的真机、200% 缩放或帧性能单独标记，不以截图推断通过。

## 产品气质

以精致、安静、适合长时间阅读的聊天工具为方向。中性色背景、清楚的文字层级、少量平台色提示；浅色和深色主题共用语义设计变量。避免大面积炫光、过度毛玻璃和装饰性仪表盘占据聊天区域。

React + TypeScript + Vite 为基线，Tailwind CSS 管理样式，shadcn/ui 提供可定制交互基础，Lucide 提供统一图标。优先复用成熟组件，再统一排版、间距、圆角、悬浮态和选中态，不重做通用弹窗、菜单与键盘导航。

## 布局

- 桌面：窄导航栏、会话列表、消息区；详情抽屉按需打开，不挤压主阅读区。
- 平板：空间足够时双栏，窄屏时保留单会话主视图。基于可用宽度调整，不用设备名称硬编码。
- 手机：会话列表与聊天详情分层导航，明确返回入口；输入区处理安全区和软键盘遮挡。
- 会话项包含头像、名称、平台/账号标识、时间、消息摘要、静音与未读状态；相同昵称仍能区分来源。
- 跨平台入口支持“全部 / 微信 / QQ”过滤。平台标识服务于身份辨认，不以整页品牌色分割产品。

## 消息与输入

- 气泡宽度限制、中文行距、时间分组和附件卡片统一。原生文本选择与复制保持可用。
- 中文输入依赖浏览器 composition 事件，组合输入期间 Enter 不发送；组合提交与发送不得触发重复消息。
- 默认 Enter 发送、Shift+Enter 换行，并允许用户切换；触屏保留明确发送按钮。
- 草稿按平台、账号、会话隔离；切换会话后不能把旧输入发送到新对象。
- 上传、发送失败与结果不确定状态直接显示在对应消息或附件上，不只用一闪而过的 toast。
- 长列表使用成熟虚拟滚动方案；加载更早历史时保留阅读位置。用户已向上阅读时不强行跳到底部。
- 使用用户本地时区显示时间，服务端保留明确时区信息。
- MVP 包含图片、视频附件、表情包和小程序卡片的能力感知展示。安全网页链接可打开；只有 appid/path 的小程序卡片不伪造网页 URL，也不承诺在浏览器运行。
- QQ 邮箱入口指向官方网页，不携带 QQ 登录令牌；管理会话退出与平台账号登出须分开表达。

## 状态与可访问性

- 区分无会话、无搜索结果、历史尚未同步、账号离线和接口不支持。
- 平台已读和本地未读不是同一状态；未支持的操作不伪装成功。
- 关键触控操作目标至少约 44 CSS px；键盘焦点清楚，控件提供可访问名称。
- 不仅依赖颜色表达平台、在线和错误状态。遵循 reduced-motion，确保文字对比度和浅/深主题可读性。
- 提供通知权限说明，用户主动开启后再请求权限。网页关闭后的系统推送属于后续能力，不以页面内事件流冒充。
- 常规聊天页面不展示协议名、Rust crate 名、内部游标等实现细节；诊断信息集中在设置的高级页面。

## 第一版界面验收

用合成数据覆盖中文长消息、同名跨平台联系人、群聊、附件缺失、发送中/失败/不确定和离线状态。再接入真实后端，核对接口状态与实际展示。

浏览器模拟平板只能证明布局与部分交互；iPad 软键盘、输入法、旋转和后台恢复需真实设备确认。没有真机证据时保持“待验收”，不阻止其他已授权工作继续推进。
