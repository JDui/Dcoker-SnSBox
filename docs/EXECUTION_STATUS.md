# 实施计划与阶段证据

日期：2026-11-15。目标：Docker / Linux AMD64，统一浏览器聊天界面。

## 分工

| 责任方 | 范围 |
| --- | --- |
| 主线程 | 目标与资料兼容计划、实现审查、集成验证、重要阶段 commit |
| Sol Max 前端线程 | web/、前端实施记录；React/TypeScript、响应式聊天、真实 API 状态 |
| Astra High 后端线程 | Rust、API 合约、适配器、SQLite、Docker/Compose、后端实施记录 |

两个实现线程共用工作目录，按文件所有权工作，不切换分支、不独立 commit；主线程只提交已审查的阶段文件。

## 交付节点

1. **P1 执行基线**：更新 MVP、资料安全边界和线程分工；提交文档。
2. **P2 可运行产品链路**：Rust API 合约、前端、真实上游连接配置及明确的不支持状态；验证必要构建和关键风险后提交。
3. **P3 AMD64 集成**：构建容器、隔离启动、鉴权/健康检查、资料只读与重启持久化检查；修复集成问题后提交。
4. **P4 真实接入验收**：分别验证微信和 QQ 登入、会话、文本收发、媒体、历史、退出和重启恢复。需要测试账号和上游运行环境；未取得证据的项保持未验证。

P2/P3 工程完成不代表原路线 M1/M3 的双平台实用验收完成。

## MVP 能力与验收标准

| 能力 | 验收要求 |
| --- | --- |
| 登入/登出 | SnSBox 管理会话与平台账号分别处理；不能以退出网页冒充平台登出；扫码失效、离线有明确状态 |
| 会话与文本 | 平台、账号、会话身份隔离；发送结果区分接受、失败、不确定；默认不自动重发 |
| 图片/视频/表情包 | 根据上游分别验证读取、预览、发送；附件视频不等同音视频通话；缺失媒体有提示 |
| 小程序链接 | 卡片信息与安全网页链接可展示；无可打开 URL 时说明必须原客户端打开，不伪造网页地址 |
| QQ 邮箱 | 跳转官方 https://mail.qq.com/，不传递 QQ token，不承诺邮箱免登录 |
| 历史 | 分页和搜索明确数据范围；保留旧目录不等于可解密或已导入；未知消息保留提示 |
| config 共用 | 原目录不移动、不改名、不删除；默认只读观察；写入接管采用单一写入方和可恢复备份 |
| 容器部署 | linux/amd64、多阶段、持久数据独立、最少权限、健康检查；不操作现有 WS 实例 |
