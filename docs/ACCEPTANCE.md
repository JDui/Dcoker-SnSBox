# MVP 验收与后续路线

本清单用于区别工程实现与真实可用性，不要求每次改动重复全部检查。每阶段仅执行其最大不确定性对应的项目，记录日期、客户端/上游版本和结论，不记录真实消息、二维码或令牌。

## 工程集成

- 使用空白自有数据卷与合成 WS 目录，构建并启动 linux/amd64 容器；打开浏览器确认真实空状态，演示数据必须主动进入。
- 未登录时不能读账号、历史或附件；登录后修改请求必须带 CSRF；注销管理会话后缓存不能继续显示私人内容。
- 源 config 只读挂载，自有数据独立。误把自有目录设进源目录时在写入前拒绝；识别目录存在不能显示“历史已兼容”。
- 用一个受控上游夹具验证会话→文本提交→回执→历史；重复幂等键不会重复调用上游，改请求返回冲突，提交超时保留不确定状态。
- 重启同一数据卷，已有历史和事件继续存在，未决发送不自动重投；浏览器草稿不能串到其他会话。
- 只检查一个桌面宽度和一个手机宽度的主要流程，中文组合输入期间 Enter 不发出消息。iPad 真机单独记录。

## 真实平台验收

对微信和 QQ 分别记录，不以一侧成功代表双平台成功：

1. 配置固定版本的上游，使用测试账号完成登录。记录是否扫码、是否支持远程登出以及下一次启动的恢复方式。
2. 打开一段已有会话，接收一条新文本，再人工发出一条测试文本；分别记录本地提交、上游接受、对端实际收到，不能混称成功。
3. 在同一会话中验证一张图片、一段短视频、一个表情。记录接收展示和发送各自结果，不把只有占位卡片视为媒体可用。
4. 查看一个小程序卡片；有安全网页 URL 时打开，没有时显示原客户端打开提示。QQ 邮箱应打开官方网页，是否另需登录单独说明。
5. 检查已知历史能否分页读取和搜索长消息后半段；标明只含 SnSBox 累积历史、上游近期历史或导入历史，不声称完整。
6. 停止并重启 SnSBox，再重启接入后端，分别记录账号恢复和消息缺口。最后验证平台登出，确认不会删除已有历史文件。

## WS 资料验收

先在停止写入后得到的一致性副本上验证，不直接实验唯一一份资料。记录原客户端版本、实际布局与上游支持格式；不能因文件名相同就转换数据库。

目录保全通过后，再验证旧令牌恢复和历史读取。若协议后端要求独占运行，停止原官方客户端再测试；回到 WS 时验证原客户端能读取资料。任一项失败即保持“不可无缝切换”，保留原资料与独立登录方案，不反复改写源文件。

## 后续优先级

1. **接入可靠性**：解决真实账号登录恢复、事件断线缺口、媒体读取与历史范围；这是 MVP 完成条件。
2. **日常聊天**：引用、@、撤回、未读、文件传输、长会话阅读位置和通知。按平台能力逐项开放。
3. **运维**：上游版本升级/回退、自有数据库一致性备份恢复、缓存配额与清理、长时间运行资源观测。
4. **设备体验**：iPad 中文软键盘、旋转、后台恢复、手机附件选择；模拟浏览器不替代真机。

音视频通话、小程序运行、支付和朋友圈不因展示了链接或视频附件而成为已实现功能。未明确授权的自动回复、跨平台自动转发保持不在范围内。
